WAN TRAINING · DISTRIBUTED SYSTEMS

一张图理解多卡训练

DP、SP、FSDP 和 HSDP 不是四种互斥模式。它们分别决定样本、序列和模型状态怎样分配给 GPU；HSDP 再决定是否复制多个参数分片组。

对象：当前 minWM Wan 训练代码视角：8 个 GPU 进程重点：权重聚齐的显存与通信

01 · 四种并行分别切什么

先分清“数据”“计算中的激活”和“模型状态”，后面的通信操作才有明确含义。

DATA AXIS

DP · 数据并行

不同副本并行读取不同样本。同一副本内部的 SP 进程读相同样本索引。

切的是 batch / samples
SEQUENCE AXIS

SP · 序列并行

一个副本的多张卡合作处理同一样本的不同序列片段；attention 中用 all-to-all 交换布局。

切的是 sequence activations
PARAMETER AXIS

FSDP · 全分片数据并行

参数、梯度和优化器状态常驻分片；运行某个 block 时临时聚齐它的权重。

切的是 model states
REPLICA AXIS

HSDP · 混合分片数据并行

建立多个 FSDP 分片组副本。每组内分片；组间还要同步梯度。

增加 shard-group replicas
总 GPU 数=DP 副本数×SP 组大小　｜　全局 batch=DP 副本数×每副本 batch

02 · 交互式 8 卡拓扑

改变 SP 和 HSDP 分片规模，观察同一批 GPU 如何形成数据副本、序列组和权重分片组。这里固定 tp_size=1、每副本 data.batch_size=2。

03 · 一个 Transformer block 的权重聚齐时间线

FSDP 的 all-gather 聚齐的是当前 block 所需权重；SP 的 all-to-all 交换的是 attention 激活。二者不是同一次通信。

1

静置：参数分片

每个 rank 常驻持有当前分片组内的一部分权重。优化器状态也随本地分片放置。

2

前向前：all-gather

FSDP hook 在分片组内聚齐当前 block 权重；必须有足够空间容纳临时完整权重。

3

前向：本地计算 + SP

各 rank 用聚齐的权重计算自己的激活；Wan attention 在 SP 组内执行 all-to-all。

4

释放 / 反向

reshard_after_forward=True 时，前向后释放完整权重；反向需要时再次聚齐。

5

reduce-scatter + 更新

梯度在分片组内汇总并分片；每个 rank 更新自己持有的参数分片。HSDP 还涉及副本间汇总。

权重 all-gather 不是把整个模型一次性复制到每卡；这份代码按 Transformer block 调用 fully_shard()。但临时完整 block、通信缓冲区和激活仍会形成显存峰值。SP 的最终 sp_all_gather(x) 也可能让每卡短暂持有完整序列激活。

04 · 两类 all-gather，不要混为一谈

“聚齐后内存不够怎么办”必须先问：聚齐的是权重，还是序列激活？

FSDP 权重聚齐

按 block 临时聚齐。缩小分片边界和前向后重新分片可压低峰值；计算与预取重叠则可能增加同时存活的缓冲区。

SP 激活聚齐

若后续层要求完整序列，每卡必须能容纳完整激活。增大 sp_size 无法消除这一处的完整张量，需调整 batch、序列长度或后续计算布局。

HSDP 的取舍

分片组缩小后，权重聚齐只在组内发生；但每个组各有一份参数分片集合，总模型副本数增加。
